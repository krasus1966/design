# Orbit 低代码控制台 · 设计标准

> 这份文件定义"什么算好看"。它是后续每一轮改动的裁判，也是评审时的对照表。
> 设计系统：**shadcn**（已锁定，不再讨论配色与字体方向）。
> 最后更新：2026-09-11

---

## 1. 受众

| 优先级 | 角色 | 使用场景 | 他们真正在问什么 |
|---|---|---|---|
| P0 | **业务搭建者**（财务 / HR / 市场部门的"低代码负责人"） | 每天上午打开，配置单据、看提交量、催审批 | "今天有没有事等我处理？" |
| P0 | **平台运维 / 研发** | 数据源同步失败时进来定位 | "哪个环节坏了？" |
| P1 | **部门负责人 / 评审人** | 一周看一次，或第一次接触这个系统 | "这东西靠不靠谱？" |

**关键推论：** P1 人群只做视觉判断，且只看 5 秒。他们的结论完全由**密度、一致性、对齐精度**决定，与动效和配色无关。因此"显得专业"的正确做法是把瑕疵清零，而不是加大视觉冲击。

---

## 2. 业务目标

1. **异常优先于总量。** 首屏必须让搭建者在 30 秒内发现待办与异常，而不是先看到一串漂亮的总数。
2. **定位快于浏览。** 运维场景下表格与状态必须是可筛选、可搜索的真控件，不能是装饰。
3. **可信先于惊喜。** 页面上出现的每一个数字都要在同一个应用内自洽（KPI、图表、表格、时间线互相对得上）。数值打架比配色难看严重得多。

---

## 3. 品牌气质

**冷静、克制、可信。** Orbit（轨道）的隐喻是"有序、可预测、在轨运行"。

由此推出的三条硬性取向：

- 界面是一件**工具**，不是一次演讲。所有"表达"通过结构与精度传达，不通过装饰。
- **不预测用户、不抢注意力。** 没有任何元素可以比用户的当前任务更醒目。
- **沉默的精度**：对齐、间距、基线这些看不见的地方必须零误差，因为 P1 人群正是靠这些下判断。

反面气质（明确禁止）：热闹、促销感、玩具感、演示 PPT 感。

## 4. 风格参考

**取这些品质，不抄任何一家公司的视觉语言或组件形态：**

| 参考对象 | 只借鉴这一件事 | 不借鉴 |
|---|---|---|
| shadcn/ui 官方文档 | 单色骨架 + 一处强调色的克制方式；边框即层级 | 不做像素级复刻，不引入其未使用的组件 |
| 高密度生产力工具的**信息组织方式** | 如何靠留白分组织、而不是靠卡片堆叠 | 不抄其色调与动效风格 |
| 数据看板的**图表克制** | 单序列单色、网格线退到背景、坐标轴不喧宾夺主 | 不使用任何图表库皮肤 |

**本原型的既定方向（保持）：** 手写内联 SVG 图表、无第三方依赖、深浅双主题、纯黑白强调色。

## 5. 信息密度

**目标：1440×900 视口下**

- 概览页首屏：4 个 KPI + 1 张趋势图 + 1 张分布图，不需要滚动
- 表格页首屏：≥ 8 行数据可见
- 行高 40–44px；面板内边距 20px；模块间距 20px；同一面板内元素间距 12–16px

**密度的获取方式：减少装饰，而不是缩小字号。**

- 正文字号下限 12px（仅用于元信息），可读正文 13px 起，标题 16px 起
- 禁止用 11px 以下的字号换取密度
- 禁止用 `letter-spacing` 负值换取"紧凑感"

## 6. 色彩标准

1. **单色骨架 + 一个强调色。** `--accent`（纯黑）只承载两个语义：**选中**与**主操作**。

   强调色分两类，约束不同——约束的是**视觉权重**，不是元素个数：

   | 类型 | 包含 | 上限 | 理由 |
   |---|---|---|---|
   | **强调型** | 实心主按钮、选中的导航项 / 分段项 / 页码 | **同一屏 ≤ 2 处** | 它们在与用户的当前任务争夺注意力 |
   | **状态型** | 开关轨道、勾选框的填充 | 不限个数，但**着色总面积 < 视口 1%** | 它们只编码某个控件的开/关，不构成"召唤" |

   实测（1440×900）：强调型——概览 1 / 图表 1 / 表格 2 / 通知 0 / 成员 1 / 单据 1 / 设置 1，全部 ≤ 2。
   状态型——通知页 3 个轨道 0.19%、设置页 2 个轨道 0.13%，均远低于 1%。
2. **语义色只表示状态**（成功/警告/危险），总像素占比 < 5%，绝不作为装饰或"第 4 个序列色"。
3. **所有派生色由 `color-mix()` 从 token 推导。** `:root` 之外不出现裸 hex。
4. **对比度硬阈值：**
   - 正文 ≥ **4.5:1**
   - 大字（≥18.66px bold 或 ≥24px）与图标 ≥ **3:1**
   - 交互态（hover / focus / active）**不得低于**默认态对比度
   - 禁用态是唯一允许降低对比度的状态

   **已记录的一处例外——开关的 OFF 态。** 关闭状态的轨道边界实测 **1.24:1（浅色）/ 1.22:1（深色）**，低于 WCAG 2.2 SC 1.4.11 对"识别组件与状态"要求的 3:1。这是 shadcn/ui 自身的设计（未选中 = `bg-input` + `border-transparent`），不是本原型的偏差。**保留理由：** 状态本身没有歧义——滑块位移 16px，且 ON/OFF 的填充色相差 21:1（实测），用户不会误判开关状态；而要把 OFF 轨道提到 3:1 需要约 `#959595` 的深灰填充，会让"关闭"看起来和"开启"一样重，直接违背"不抢注意力"。**边界条件：** 只有 OFF 态适用；ON 态实测 21:1（浅）/ 17.65:1（深），滑块自身另有 `--elev-raised` 阴影勾边。若将来该开关成为唯一的状态指示（即不再有 16px 位移这类形状差异），此例外作废。
5. **深浅色是两套独立取值**，不是自动反转。语义色在深色下必须单独选取步进值。
6. **表格与图表中的文字一律穿文字色 token**，绝不穿数据色——身份由旁边的色块承担。

## 7. 字体标准

**配对：Geist（界面与正文）+ Fira Code（数字）。** 两族分工必须严格：

- **凡是"要被比较的数字"** —— 金额、编号、时间戳、百分比 —— 使用 `--font-mono` + `tabular-nums`
- 面板标题、正文、按钮使用 `--font-display` / `--font-body`

**中文排版规则（不可协商）：**

| 项 | 值 | 原因 |
|---|---|---|
| 标题行高 | **1.35** | 汉字撑满 em 框，拉丁的 1.0–1.2 会让相邻行粘连 |
| 正文行高 | **1.6** | 同上 |
| 中文负字距 | **禁止（`letter-spacing: 0`）** | 汉字在固定 em 网格上，负字距只会挤字 |
| 拉丁大标题负字距 | -0.01 ~ -0.02em | 仅用于纯拉丁字串（如品牌词） |

**字重三档：** 400 正文 / 500 强调与标签 / 600 标题。**不使用 700 及以上。**

## 8. 动效标准

**只允许三种动效：**

1. 状态过渡（hover / active / focus）：150ms
2. 视图与数据切换（切页、切周期、筛选）：200ms
3. 图表数值变化：200ms

**统一缓动：** `cubic-bezier(0.2, 0, 0, 1)`

**规则：**

- 动效不得延迟信息获取。任何让用户等动画结束才能读到数据的动效都是缺陷。
- 必须尊重 `prefers-reduced-motion: reduce`，命中时全部降级为瞬时。
- **禁止：** 入场逐元素 stagger、hover 放大、渐变扫光、视差、加载骨架屏（本原型无异步）。

## 9. 素材标准

| 类别 | 标准 |
|---|---|
| 图标 | 24×24 viewBox 线性图标，`stroke-width: 1.75`，`currentColor`。**不使用 emoji 作为功能图标。** |
| 图表 | 手写内联 SVG，单序列单色。为保证单文件自包含，**不引入图表库**。 |
| 图片 | 本原型不承载照片类内容。若未来引入（成员头像、附件预览），必须使用真实素材或明确的占位标注，禁止用生成图或手绘图替代真实指涉物。 |
| 字体 | Geist 与 Fira Code 通过远程字体加载，**必须保留完整系统回退栈**，断网时界面仍需可读。 |
| 数据 | 演示数据必须**内部自洽**（KPI ↔ 图表 ↔ 表格 ↔ 时间线互相对得上），且不使用真实企业或个人信息。 |

## 10. 反模式：什么算"AI 味 / 模板感"

出现任意一条即为不合格：

1. 紫蓝渐变，或每一层背景都叠渐变
2. emoji 当功能图标
3. "左侧彩色竖条 + 圆角卡片"的 callout 块
4. hover 时文字变灰、变淡
5. 手绘 SVG 小人 / 场景
6. 同一视口内，同一个动作出现多个实心按钮
7. 每个标题旁边都配一个图标
8. 编造指标、无意义占位文案（"示例文本"、"Lorem"、"数据 1"）
9. 默认暖米色 / 奶油色背景
10. 只有设计者或演示者才需要的控制面板
11. **模板对称**——卡片等高等宽、文案等长。真实数据必须长短不一。
12. **"看起来能点但其实不能点"的控件**——假搜索框、假分页、假筛选、假开关。**这是本原型目前最大的模板感来源。**

## 11. 验收阈值（可逐条核对）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 正文对比度 | ≥ 4.5:1（深浅两套主题分别核对） |
| 2 | 大字 / 图标对比度 | ≥ 3:1 |
| 3 | 交互态对比度 | ≥ 默认态 |
| 4 | 焦点可见性 | 每个可聚焦元素都有 ≥ 2px 可见焦点环，键盘可达时不被隐藏 |
| 5 | 中文标题行高 | ≥ 1.3 |
| 6 | 中文负字距 | 0 处 |
| 7 | 强调色用量 | 强调型（实心主操作 + 选中态）同一屏 ≤ 2 处；状态型（开关轨道等）不限个数，但着色总面积 < 视口 1% |
| 8 | 图表数据编码 | 有填充（非空心轮廓）；柱状图每根柱同时有**分类标签**和**数值标签** |
| 9 | 图表数值来源 | 柱长由 `--v / --max` 计算，不存在手写的百分比魔数 |
| 10 | 网格线 | 只在不误导比例的前提下存在；无标注的假刻度必须删除 |
| 11 | 数字一致性 | KPI / 图表 / 表格 / 徽标 互相对得上 |
| 12 | 控件真实性 | 没有任何"看起来能点但不能点"的控件 |
| 13 | 布局完整性 | 无重叠、无裁切、无溢出，表头与单元格同边对齐 |
| 14 | 裸 hex | `:root` 之外 0 处 |
| 15 | 减少动效 | `prefers-reduced-motion` 下全部降级 |
| 16 | 组件边界对比度 | 控件轮廓 ≥ 3:1（WCAG 2.2 SC 1.4.11）。**唯一豁免：开关 OFF 态**，见 §6.4 记录的理由与边界条件 |
